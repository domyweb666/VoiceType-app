# 技術選型決定（待米定）

**狀態**：❓ 未決定。這是米的決定，Agent 只列代價。**決定欄米親口確認後才寫。**
**背景**：米選了「只做 iOS」。現在的程式是 Flutter，同時跑 Windows／Android／iOS。只做 iOS 之後，要不要繼續用 Flutter，代價不一樣。

## 兩條路的代價

| | 留在 Flutter，只改 iOS 介面 | 改寫成 SwiftUI |
|---|---|---|
| 已經寫好的東西 | 轉錄、長錄音分段、重試、加密儲存、待轉錄佇列全部留著 | 服務層全部重寫一次（OpenAI／BytePlus 呼叫、切段、重試、加密存檔） |
| 系統免費送的行為 | 要自己接：系統字級（審查 #18 就是沒接好）、讀屏標籤（#19）、左緣返回、系統半頁與動作表的樣子 | 用系統元件就有：動態字級、讀屏、返回手勢、深色與增加對比 |
| 錄音中的靈動島、鎖定畫面狀態 | 必須另外寫 Swift（WidgetKit／Live Activity 只能原生寫），兩種語言並存 | 同一種語言 |
| 捷徑、動作按鈕、Siri | 必須另外寫 Swift（App Intents），兩種語言並存 | 同一種語言 |
| 沒有 Mac 的開發迴圈 | 邏輯可以在 Windows 上跑測試；iOS 介面一樣只能靠 CI 建置看真機 | 幾乎全部只能靠 CI 建置看真機，沒有 Xcode 預覽，每改一次等一輪建置 |
| 設計代號檔 | `05-設計代號/Tokens.swift` 要翻成 Dart（語意名稱照抄） | 直接用 |
| 讓 AI 分輪寫程式 | 兩種語言 → 兩份代號檔要同步，漂移風險高 | 一種語言、一份代號檔 |

## 前置條件（不管選哪條都要先過）

- **能把版本裝到真機**：目前是 `.github/workflows/ios-release.yml`（GitHub Actions 的 macOS 機器）＋ TestFlight，六個 iOS secret 還沒設。這條路通了，閘門 3 才能開。GitHub Actions 的 macOS 規格與 TestFlight 規定會變，用前查證。
- **不准用模擬器替代**：模擬器沒有觸覺、沒有手指遮擋、延遲不同（🔴「模擬器上順，手機上就順」）。

## 舊介面丟掉還是改？

舊的 Flutter 介面（深色編輯器風、桌面三欄）跟新設計差太多，不管哪條路，**介面層都是重做**，能留的是服務層。
不管選哪條，**至少保留**：`04-手感/參數表.md` 與 `05-設計代號/` 這兩份，它們跟語言無關。
