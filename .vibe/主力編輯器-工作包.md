# 組塊 Y：主力編輯器（2026-11-24 米：「全做，不過開多個 subagent 做」）

意圖：知識型創作者把米說當主要文字編輯工具，文章在裡頭寫完，複製就能貼到其他平台。
不做：iPad、iCloud 同步（第 8 項，前面做完再談）、圖片、表格、自動發文、穀倉、逐字對準。「學到的習慣」等米驗完再決定拿不拿掉，這輪不動。

## 共同規則（每一包都適用）

- 動工前讀：`.vibe/規矩檔.md`、`.vibe/安全標準.md`、`.uiux/05-設計代號/使用規則.md` 與 `詞彙表.md`、你要改的檔案與鄰近檔案。
- 只在自己的 worktree 裡改，只改「准許改的檔」。一定要多改別的檔才編得過時可以改，報告裡列出來。
- 做完在自己的分支 commit（pre-commit hook 要過，不准 `--no-verify`）。不准 push、不准切分支、不准打 tag。
- 沒有本機 Swift 編譯器。編不編得過靠你仔細讀型別與既有簽名，CI 只在整合後跑。寫完把每個新呼叫對一次簽名。
- 部署目標 iOS 17；iOS 18 的 API 要 `#available`。Swift 5.10 語法。
- SwiftLint `--strict`：檔案 300 行、函式 40 行、型別本體 200 行、一行 100 字（中文一字算一）都是紅燈；識別字至少 3 個字（x、y、id 例外）；不准 `Bool?`、`!` 強制解包、`try!`、空 catch、`TODO`、裸數字的 padding／spacing／cornerRadius／duration；import 照字母排；多行集合結尾要逗號；型別最多巢一層。多行條件的大括號：SwiftFormat 與 SwiftLint 要求相反，條件寫成單行或先拆成 `let`。
- 檔案快滿 300 行就拆到 `型別+用途.swift`。extension 在別的檔時，用到的 `@State private` 要拿掉 private。
- 宣告上方註解用 `///`，函式體內用 `//`；註解只寫為什麼。文案臺灣繁體、短、講人話，按鈕用動詞帶對象；不用「不是…而是…」。
- `ios-native/MiSayTests/` 用 XCTest，純函式都要有測試；改到既有行為的測試一起改。
- 不准新增第三方套件、不准連 api.openai.com 以外的地方；文字稿不進 log。
- 格式：commit 前每個改過的 .swift 跑 `bash <主對話給的 fmt.sh 路徑> <檔>`（照 `.swiftformat` 重排，換行字元照舊）。
- 不要停下來問。要決定的事選最保守、最好改回來的做法，報告標「待確認」。同一個問題試 3 次不行就停手回報。
- 報告 300 字內：做完什麼／改了哪些檔／自己查過什麼／待確認／還沒做的。

`Transcript` 已加欄位：`title`、`publishedAt`、`sourceID`、`sourceKind`、`trashedAt`（都是 optional，舊檔讀得出來）。改寫來的篇不進「從修改學習」（`unlearnedEdit`）。

## 第一波（三包平行）

### Y1 出口：複製出去是乾淨的
准許改：`Backup/MarkdownExport.swift`、`Backup/MarkdownFolder.swift`、新檔 `Backup/PlainTextExport.swift`、`Backup/HTMLExport.swift`、`Backup/DraftPasteboard.swift`、新檔 `Screens/Transcripts/ExportSheet.swift`、`Screens/Transcripts/ThreadsParts*.swift`、`TranscriptDetailView+Export.swift`、`TranscriptDetailView+Editing.swift` 的 `copy()`、`TranscriptDetailView+Menu.swift` 的 Markdown 兩項、`TranscriptDetailView.swift` 的分享鈕、`TranscriptTextFile.swift`、`RecordingResultView.swift` 的剪貼簿那一行、對應測試。
- `PlainTextExport`：Markdown → 乾淨純文字。`#` 標題去記號、`**`／`*`／`` ` `` 去記號、`- ` 變「・」、`1. ` 留、`> ` 去記號、`[字](網址)` 變「字（網址）」、三個以上連續換行縮成兩個。只處理看得出是記號的（例如行首 `#` 後面要有空白），「C#」「#標籤」「2*3」「snake_case」不能壞。
- `HTMLExport`：Markdown → 一小段 HTML（h2/h3/p/strong/ul/ol/blockquote/a）。內容一律跳脫，連結只准 http／https。App 裡不渲染 HTML（安全標準五），只放進剪貼簿。
- `DraftPasteboard.copy`：同一個 item 同時放 `public.utf8-plain-text`（乾淨純文字）與 `public.html`。詳情頁複製、錄音完成的自動複製都走它。另有 `copyMarkdown`。
- `ExportSheet`（「匯出」）取代頂上的分享鈕與「⋯」裡的兩項 Markdown：複製標題（有標題才出現）、複製全文、複製成 Markdown、分享文字（ShareLink 給 String，不是檔）、存成文字檔（.txt，走系統分享）、存成 Markdown 到資料夾、換資料夾。檔名與 Markdown 檔頭用 `title`（有的話）。複製正文不帶標題。
- `ThreadsParts`：純函式把「1/」「2/」開頭的串文拆成幾篇，加一個 `ThreadsPartsView`（每篇一張卡：字數、超過 500 字標出、「複製第 N 篇」），還不接畫面，Y5 接。

### Y2 資料安全與清單：垃圾桶、備份、版本、標題、排序、狀態
准許改：`Storage/*`、`Backup/Backup.swift` 與新檔 `Backup/AutoBackup.swift`、`Screens/Settings/BackupSection.swift`、`EraseAllDataSection.swift`、新檔 `Screens/Transcripts/TrashView.swift`、`TranscriptListView*.swift`、`PendingQueue/RetainedRecordings.swift`、`App/` 進入點（掛清垃圾桶與自動備份）、對應測試。
- 垃圾桶：清單與詳情刪除改成進垃圾桶，30 天後才真的刪；清單右上或底部有「垃圾桶」入口，可放回、可立刻刪（確認）。5 秒「已刪除・復原」照舊。垃圾桶裡的篇不出現在清單、統計、搜尋、備份；它的留存錄音不可被當孤兒刪掉，真的刪除時才一起刪。自己打的空白新文稿照舊直接刪。「刪除全部資料」要連垃圾桶一起清。流水裡接著錄後刪暫時篇那種程式自己刪的照舊直接刪。垃圾桶裡的篇解不開時另存不刪。
- 一律「寫成功才刪舊的」。
- 備份：記上次匯出時間，設定備份區寫「上次備份：…」；加「自動備份到資料夾」（預設關，使用者自己選資料夾，一天最多一次、內容有變才寫、留最近 7 份、寫入用原子寫入；失敗記在備份區讓人看到）。說明講清楚：備份檔沒加密；換新手機時 iCloud 還原的文字稿解不開，要靠備份檔。加密金鑰的 Keychain 屬性**不准動**（等米決定）。
- 版本：最近 8 版照留，再加上更早的每天留最後一版、最多 14 天；`VersionsSheet` 說明文字跟著改。
- 清單：有標題顯示標題（粗一級）＋一行內文，沒標題照舊；改照 `updatedAt` 排序與分組（不要為此改 `updatedAt` 的語意；學習寫回不可讓它跳到最前面，查一下）；改寫來的篇副標寫「改寫：種類」不寫「自己打的」；已發布的列有「已發布」字樣；標籤選單旁可篩「草稿／已發布」。搜尋含標題。清單列左滑有「標成已發布／改回草稿」。
- `TranscriptDetailView` 這個檔不要動（標題欄 Y4 做）。

### Y3 AI：換回定案模型、自己講怎麼改、整篇回饋
准許改：`Polishing/*`、`Settings/AppSettings.swift` 的模型那幾行、`Screens/Settings/AdvancedSettingsView.swift` 的模型那一區、`DraftEditor.swift` 的 passageMenu 一帶與 `PlainDraftEditor+Passage.swift`、`PassagePreviewSheet.swift`、新檔 `Screens/Transcripts/ReviewSheet*.swift`、`TranscriptDetailView+Review.swift`、`TranscriptDetailView.swift` 加一個 sheet 與狀態、`TranscriptDetailView+Menu.swift` 加一項、對應測試。
- 模型：預設 `gpt-6-luna`、第二選項 `gpt-5.4-mini`、拿掉 `gpt-4o-mini`（2026-11-07 米定案，從沒進程式）。寫之前上 OpenAI 官方文件查證模型名、chat completions 參數（reasoning 預設 medium，要明講 none 或 low；temperature 收不收），查不到就不要猜，報告寫明。存著舊模型名的人落到預設。設定裡的模型選單拿掉（創作者看不懂），存的值照讀。

- 整篇回饋「⋯ → 請 AI 看整篇」：三種各自按才送：①下標題（5 個候選，點一個就設成 `title`）②開頭夠不夠力（指出問題與方向，不代寫）③讀者會卡在哪（最多 8 條，每條一句原文引文＋原因，點了跳到那一句；引文在正文找不到就不給點）。只給意見，不改稿。提示詞寫死、system 與 user 分開、輸出嚴格 JSON 並驗結構、當純文字顯示。超過 3 萬字不送。重試次數照既有。

### Y4 編輯頁：標題欄、新編輯框轉正、格式、補錄不離開、點字數設目標
准許改：`TranscriptDetailView.swift`、`TranscriptDetailView+Writing.swift`、`+Editing.swift`、新檔 `TranscriptDetailView+Title.swift`、`+RecordHere.swift`、`DraftEditor*.swift`、`PlainDraftEditor*.swift`、`PlainTextView*.swift`、新檔 `FormatBar.swift`、`MarkdownFormatting.swift`、`MarkdownLineStyle.swift`、`+Menu.swift` 的「字數目標」與「接著錄」、`RecordingSheetView*.swift`、`RecordingResultView*.swift`、`HomeView.swift`（只准抽共用）、`App/RecordingLauncher.swift`、`PendingQueue/TranscriptionQueue+Polishing.swift` 的接回邏輯、`AppSettings.swift` 的 `usesPlainEditor`、`AdvancedSettingsView.swift` 那個開關、對應測試。
- 標題欄：正文上面一行「標題」（可多行、`Token.Fonts`、沒填顯示淡字），改了停 1 秒存進 `transcript.title`（空白存 nil），離開也存。還沒有文字稿的篇也能取標題。按鍵盤下一步跳到正文。標題欄跟著捲不跟著捲都可以，選最穩的；打字時鍵盤升起，正文至少還有七行。

- 格式列抽成一個 `FormatBar`，兩種編輯框共用：標題、小標（`### `）、粗體、清單、編號清單（選到的多行依序 1. 2. 3.）、引言（`> `）、連結（選到的字變 `[字](網址)`，跳一格問網址；只收 http／https，沒選字就插網址）。橫向可捲，鍵盤上方放得下。標題與小標互斥（切換時換記號不疊）。`MarkdownLineStyle` 補小標、編號、引言的樣子。連結維持原樣顯示即可。
- 補錄不離開：在編輯頁按麥克風或「⋯ → 接著錄」，直接在這頁升起錄音面板，不切分頁、不 dismiss。錄完整理好，字插回游標處（或接在最後），面板收起後編輯框顯示新內容、捲到插入處。要看懂 `queue.openForEditing`、`insertionsMovedToEnd`、`reloadFromStore`、`InsertionPoint` 與流水的存檔順序：編輯頁開著時流水把字接進存檔，手上那份不可以蓋掉它，流水也不可以蓋掉手上還沒存的字（先 flush 再錄，錄音期間編輯框不可打字因為面板蓋著；面板收起來但流水還在背景跑時要處理）。Recorder 同時只能錄一段，首頁那條路照舊可用。接不上就照舊退回「待轉錄／獨立一篇」，不可掉字。
- 字數：點底下（或打字時頂上）的字數開目標選單；「⋯」裡那一列拿掉。
