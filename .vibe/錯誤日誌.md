# 錯誤日誌

> vibe-no-repeat-error 寫入。白話，米讀得懂。每條的「下次怎麼避免」都回灌到規矩檔。

## [2026-10-31] 雲端 Mac 上沒有說好的檢查工具
- 發生什麼：第一次推 A1 上 GitHub，規矩檢查那步直接說「找不到 swiftlint」。我事前查過 GitHub 的說明文件，上面寫這個工具已經裝好了，實際沒有。
- 為什麼會這樣：GitHub 的雲端機器說明文件跟實際機器不同步。信文件沒信機器。
- 下次怎麼避免：CI 要用的工具一律自己從官方下載、釘死版本、驗 SHA-256，不依賴雲端機器「應該有裝」。

## [2026-10-31] 註解寫法讓格式檢查紅燈
- 發生什麼：測試函式上方的說明用了一般註解（兩條斜線），格式檢查要求宣告上方要用文件註解（三條斜線）。
- 為什麼會這樣：SwiftFormat 的 docComments 規則，我沒查就寫。
- 下次怎麼避免：Swift 裡函式、型別、屬性上方的註解用 `///`，函式裡面的用 `//`。

## [2026-10-31] 自審抓到寫死路徑與多餘設定
- 發生什麼：工作流程寫死了雲端 Mac 上 Xcode 的路徑（標準清單明寫不准），專案描述檔多了七個沒人要求的設定（規矩第 3 條）。乾淨審查員抓到，推上去前砍掉。
- 為什麼會這樣：寫的時候「順手」加了以為有用的東西。
- 下次怎麼避免：寫完先對標準清單「絕對不准做」逐條掃一次，再對 diff 每一行問「哪句話要我加這個」，答不出來就砍。

## [2026-11-01] 沒查 SwiftLint 預設規則，B2 第一推就紅
- 發生什麼：B2 推上 GitHub，規矩檢查點名三種：型別裡再包型別包到第二層（nesting）、final class 裡用了 `class func`（要用 `static`）、把回應正文轉成字串的寫法（要直接比 Data 或用 `String(bytes:encoding:)`）。格式檢查是過的。
- 為什麼會這樣：這三條是 SwiftLint 0.65 預設開的規則，我們的設定檔沒列出來，我寫的時候只對著設定檔裡有列的規則查。
- 下次怎麼避免：SwiftLint 預設規則也算數，不只設定檔列的那些。寫 Swift 時：型別最多巢一層（巢狀的搬到同一層當 private 型別）、final class 裡一律 `static`、Data 轉字串用 `String(bytes:encoding:)` 或直接比 Data。

## [2026-11-07] 金鑰在終端機外露
- 發生什麼：第 0 步腳本在終端機用看不見的輸入問金鑰。米貼上去的那一刻腳本已經因為空輸入收到 401 結束，金鑰落到 PowerShell 的提示符上，整串顯示在畫面、存進 PowerShell 歷史檔；我讀終端機確認結果時看到了，等於進了對話紀錄。
- 為什麼會這樣：App 的終端機面板裡，Enter 和貼上的先後順序靠人手，看不見的輸入又沒有任何回饋，貼晚一步就掉到提示符。
- 當場做了什麼：刪掉 PowerShell 歷史檔那一行；請米關掉那個分頁、到 OpenAI 後台撤銷那把、換新的。
- 下次怎麼避免：不用終端機的隱藏輸入收金鑰。金鑰放 `.vibe/local/.env`（整個資料夾 git 不收），腳本自己讀，不印、不寫別處；用完米想刪就刪。
