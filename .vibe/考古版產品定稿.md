# 考古版產品定稿（Flutter 舊版實際在做的事）

**狀態**：考古版，等你逐條回反應。
**怎麼回**：每一條在「你的反應」欄填一個：**預期**（本來就要這樣）、**意外**（不知道它會這樣）、**落差**（以為有，其實沒有；或以為是 A，其實是 B）。也可以直接在對話裡跟我說第幾條。

## 二、轉錄

| # | 舊版實際在做的事 | 你的反應 |
|---|---|---|
| 8 | 超過 10 分鐘的錄音切成每段 10 分鐘，一段一段轉 | |
| 9 | 每段送 OpenAI 時，會附上「請用臺灣繁體逐字轉錄」＋你的自訂詞彙（最多 16 個）＋前一段的結尾，三樣加起來 200 字內 | |

## 新版要對得上的行為（候選）

這張表不是定案，是給 `vibe-spec-standards` 寫黃金行為用的草稿。「建議」欄是我的看法，你說了算。

| 舊版行為 | 建議 | 理由 |
|---|---|---|
| 錄音 16 kHz 單聲道 PCM | 保留 | 轉錄夠用，檔案小 |
| 超過 10 分鐘切段、逐段轉、失敗從那段續 | 保留 | 長錄音的保險 |
| 轉錄 prompt 帶繁中提示＋詞彙＋前段結尾 | 保留 | 影響轉錄品質 |
| 重試規則（哪些錯誤重試、次數、間隔） | 保留 | 已經想清楚了 |
| 待轉錄＋自動續轉、失敗就停 | 保留 | 不弄丟、不無限扣錢 |
| 轉錄成功就刪錄音檔 | **改掉** | 改成「口語稿存進歷史之後」才刪 |
| 潤飾失敗不存口語稿 | **改掉** | 口語稿先存，潤飾失敗也看得到、可以重試 |
| 錄音中被關掉就不見 | **改掉** | 錄音中定期把聲音寫成可救回的檔，重開時收進待轉錄 |
| 歷史打不開就整盒刪掉重建 | **改掉** | 打不開就先備份壞檔、提示你，不自動刪 |
| 自動複製沒開關 | 改掉 | 設定頁補開關，預設開 |
| 金鑰驗證失敗照樣存 | 保留 | 離線時也要能先存；但畫面要講清楚 |
| BytePlus 引擎 | 不做 | 記憶裡的 iOS 決定 |
