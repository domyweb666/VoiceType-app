# 「AI 語音創作工作台」規劃文稿評估（2026-11-09）

> 米 11/09 給了 `AI_語音創作工作台_產品規劃.html`，說定位改給知識工作者、功能要大改版。這份是對照現在的程式（v0.2.4，K 塊做完、還沒推）寫的評估，PRD、定稿、帳本都還沒動。
> 一句話：文稿裡第一版必做的 12 項，米說已經有 8 項；真正缺的是「潤飾風格／一份錄音多種輸出」和「編輯器能做的事」。帳號、雲端、額度三項要伺服器，跟 11/08「伺服器找人」的決定衝突，要米選。

## 一、先定一件事：給誰用

米這次講「知識工作者」，文稿寫的是「內容創作者」，兩群人要的東西不一樣：

| | 內容創作者（文稿寫的） | 知識工作者（米這次講的） |
|---|---|---|
| 例子 | 知識型 YouTuber、部落客、電子報作者、講師 | 顧問、PM、研究員、律師、業務 |
| 錄什麼 | 自己一個人講想法 | 會議、訪談、客戶通話、自己整理思緒 |
| 要拿到 | 一篇像自己寫的稿、口播稿、貼文 | 摘要、待辦、決議、誰說了什麼 |
| 必要功能 | 潤飾風格、多種輸出、編輯器 | 說話者分離、摘要範本、行事曆／會議整合 |

文稿第 4.5 節的輸出（YouTube 口播稿、Threads、電子報）全是創作者的。我建議用文稿的寫法：**知識型內容創作者**。理由是米自己就是這群人，每個功能都能自己天天用、自己驗；會議記錄那條路要做說話者分離，競品（Plaud、Otter、各家會議 AI）已經很擠。

下面的評估照「知識型內容創作者」寫。米要改成會議那條路，第三節要整個重排。

## 三、建議的下一塊：組塊 W「一份錄音變成要用的稿」

照文稿第 4.3～4.5 節，按「米自己每週會用到」排：

**W1 改寫成…（多種輸出）** 詳情頁「⋯ → 改寫成…」選一種：知識文章、YouTube 口播稿、Threads 貼文、電子報、大綱與金句。產出存成這篇底下的**另一個版本**，原本的文字稿不動。預設潤飾照舊是「保留原聲」。
- 為什麼不把六種風格放在錄音前選：錄之前多半不知道這段要拿去做什麼；錄完再選，同一段可以出好幾種，這就是文稿說的「一份錄音，多種輸出」。
- 文稿建議「先整理成結構化素材再輸出」：保留原聲那份就是素材，改寫都從它出發，不從口語稿重來。

**W2 一句話的補充要求** 改寫時可以多打一句（「保留我舉的例子」「大白話」）。⚠️ 這碰到 11/08 米的決定「潤飾提示詞不給改」。我的看法：那次拿掉的是整份提示詞的編輯頁，這次只是一句附加要求、只用在改寫、不改預設潤飾，風險小很多。要米點頭。

**W3 看 AI 改了什麼** 原本排在第三批。詳情頁切換「口語稿／文字稿」，標出刪掉和加上的字。文稿 4.2 要的就是這個，用來確認 AI 沒改掉原意。

**W4 選一段叫 AI 改** 選取文字後的選單多「縮短」「展開」「改口語」「改書面」。只送選到的那段，改完先給你看，按「換上」才換。

**W5 簡單格式** 文字稿維持純文字，加一條鍵盤上方工具列插入 `#`、`**`、`-`，存成 Markdown 時照原樣出去，Obsidian 直接看得懂。不做富文字編輯器：iOS 的富文字編輯要自己包 UIKit，工很大，跟 Markdown 匯出也對不上。

**W6 標籤與合併** 文字稿加標籤、清單能篩；選兩三篇「合併整理成一篇」。文稿放第三階段，我也建議放最後。

不建議這輪做：跨錄音語意搜尋（要向量資料庫，本機做很重）、說話者分離（gpt-transcribe 沒有，要換服務）、Notion／Obsidian API 整合（現在的存 Markdown 已經夠用）。

## 四、文稿跟之前的決定衝突、要米選的地方

1. **帳號、雲端同步、額度管理放第一版**：文稿寫第一版必做；11/08 米選「先做功能，伺服器找人」，組塊 P 等懂後端的人。我的建議維持 11/08：先用自備金鑰把 W 做完給 TestFlight 的人用，量到每月時數再談伺服器。
2. **價格**：文稿寫 Creator NT$199／10 小時、Pro NT$399／30 小時；我 11/08 算的是每小時成本約 NT$13。照這個算：
   - Creator 用滿：實收約 161、成本 130，毛利 19%。
   - **Pro 用滿：實收約 323、成本 390，每個人每月虧 67**。
   - Free 每月 60 分鐘：每個免費用戶每月花你 NT$13，沒有上限地一直花。
   文稿也寫「待驗證」，現在不用定，但 Pro 30 小時這格要改（降到 20 小時，或漲價），Free 建議改成 Apple 7 天試用、3 小時上限，一個 Apple ID 只能一次。
3. **自訂指令**：見 W2。
4. **改定位要改的文件**：`產品定稿.md` 的一句話與「不做什麼」、PRD 的使用者故事、首頁提示字（現在寫「說完會變成可以直接貼上的文字，自動幫你複製」，是短句聽寫的講法，長稿要換）。

## 五、文稿裡我覺得不用照做的

- **資料模型（User、AIJob、UsageLedger）**：那是伺服器的表。米說現在是本機檔案加 Codable，等組塊 P 才需要，不用為它改現在的儲存。
- **Android、Web 編輯器**：現在是 Swift 原生，Android 等於重寫一個 App。第一版只做 iOS。
- **「錄音結束後 5 分鐘內拿到草稿」**：S4 邊錄邊轉之後目標是一分鐘左右，比文稿寫的還快，等真機驗。
