> 這片是組塊 A 的最後一片，做完你就能從 TestFlight 裝米說，組塊 A（A1、A2、A3）一次親手驗。
> 前置：六個 GitHub secret 已於 2026-11-01 設好（gh secret list 可查）；App Store Connect 的 App 條目「米說」要先存在，不存在上傳會失敗。

## 這片是什麼（一句話）

把現有的簽章版工作流程從 Flutter 改成編 `ios-native/`，推一個 `v*` tag，雲端 Mac 就簽章、封裝、送到 TestFlight；你手機上的 TestFlight 出現米說。

## ✅ 必須做到（可操作測試句）

**GitHub 網頁**
- [ ] 我推 tag `v0.1.0`（或在 Actions 手動按「iOS Release」），應該看到一條叫「iOS Release」的工作流程跑起來，綠勾，步驟名字看得懂：「匯入憑證」「安裝 profile」「產生 Xcode 專案」「封裝」「匯出 IPA」「上傳 TestFlight」。
- [ ] 我整頁搜 `p12`、`-----BEGIN`、`password`，應該看不到任何 secret 的內容，只有被遮成 `***` 的地方。
- [ ] 推一個不是 `v` 開頭的 commit 到 main，「iOS Release」不應該跑，「iOS Native CI」照跑。

**App Store Connect 網頁**
- [ ] 我開 https://appstoreconnect.apple.com 的「我的 App」→ 米說 → TestFlight，應該看到一個 build，版本 `0.1.0`，build 號是那次 Actions 的流水號；狀態幾分鐘內從「處理中」變成可測試，**沒有**跳「缺少出口合規資訊」要你手動回答。

**手機**
- [ ] 我在 iPhone 裝 TestFlight App，用同一個 Apple ID 登入，應該看到「米說」可以安裝。
- [ ] 我裝好打開，應該看到 A2 做的首頁殼：正中央超大玉米黃鈕「說」、兩句話、左上「文字稿」、右上「⋯」。這一條就是組塊 A 的批次驗收入口。

## ⛔ 絕對不准做

- 不准動到：`ios-native-ci.yml`（A1 的不簽章流程）、`ios-native/MiSay/` 底下任何畫面與程式、`ios/`、`lib/`、`desktop-release.yml`。
- 不准把任何 secret 寫進 log、artifact、檔名；簽章素材只從 `secrets.*` 來（安全標準八 🔴）。
- 不准上傳 artifact 到 GitHub，連 IPA 都不留（安全標準八：上傳的 artifact 只能是 App 本身，這裡 App 直接去 Apple，GitHub 上一個都不留）。
- 不准擅自加：自動發 release、自動填 TestFlight 測試說明、多個 scheme、任何第三方 action 以外的工具。Apple 官方的兩個 action（匯入憑證、上傳 TestFlight）釘死版本。
- 不准改 Bundle ID、Team ID、profile 名稱；它們跟 Apple 後台對齊，改了就簽不了。
- 不准在這片開麥克風說明、圖示、截圖；送審素材是另一片。

## 🎯 每條的意圖

- 「推 tag 就跑、不是 tag 不跑」是為了日常 commit 不會每次都送一個 build 去 Apple；上 TestFlight 是你決定的動作。
- 「步驟名字看得懂」跟 A1 一樣：紅了你能說出是哪一步。
- 「搜不到 secret 內容」是安全標準八 🔴：這條工作流程在 public repo 上誰都看得到紀錄。
- 「build 號是流水號」是為了 Apple 不收重複 build 號；用 Actions 的流水號就永遠不會撞，你不用每次手動加一。
- 「沒有出口合規提示」是為了每次 build 上去都直接可測，不用你進後台點一次；米說只用 HTTPS，照規定選免申報。
- 「TestFlight 看得到、裝得起來、打開是首頁殼」是這整個組塊存在的理由：從這一刻起，之後每片你都親手驗得到。
